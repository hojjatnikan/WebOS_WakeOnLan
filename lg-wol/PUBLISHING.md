# انتشار عمومی در فروشگاه ال‌جی (LG Content Store)

راهنمای عملی از صفر تا انتشار. فرایندهای ال‌جی هر چند سال تغییر می‌کنند، پس هرجا
شمارهٔ نسخه یا نام صفحه ذکر شده، آن را به‌عنوان راهنما ببینید و فرم‌های واقعی را در
پورتال تأیید کنید.

> نکتهٔ مهم: **حساب توسعه‌دهنده** و **حساب فروشنده** دو چیز جداگانه‌اند و هر دو لازم است.

---

## ۰) قبل از هر چیز: یک تصمیم استراتژیک

اپ‌هایی که «بدون هیچ تنظیمی کار نمی‌کنند» یکی از دلایل رایج رد شدن در بازبینی هستند.
این اپ برای کار کردن نیاز دارد که **دستگاه مقصد** از قبل برای WOL آماده شده باشد
(تنظیمات بایوس و کارت شبکه). بنابراین:

- این را در **توضیحات فروشگاه** صریح بنویسید (متن آماده در بخش ۶).
- یک تصویر از صفحهٔ «عیب‌یابی» در اسکرین‌شات‌ها بگذارید تا تیم بازبینی ببیند اپ
  ابزار عیب‌یابی درونی دارد و کاربر را تنها نمی‌گذارد.
- در توضیحات توضیح دهید که **تلویزیون نمی‌تواند خودش را بیدار کند**. اگر این را
  ننویسید، امتیاز یک‌ستاره می‌گیرید از کاربری که انتظار داشته تلویزیون خودش روشن شود.

## ۱) ثبت‌نام و دریافت شناسهٔ اپ

1. **حساب توسعه‌دهنده**: ثبت‌نام در پورتال توسعه‌دهندگان ال‌جی
   (`developer.lge.com`)، بخش webOS TV. این حساب برای دسترسی به SDK و حالت
   توسعه‌دهنده لازم است.
2. **حساب فروشنده**: ثبت‌نام در **LG Seller Lounge**
   (`seller.lgappstv.com`). برای ثبت‌نام معمولاً اطلاعات شرکت/شخصیت حقوقی و
   مدارک مالیاتی می‌خواهند. تأیید حساب چند روز کاری طول می‌کشد، پس اول این را
   انجام دهید.
3. در Seller Lounge یک **اپ جدید** بسازید و **App ID** بگیرید. ال‌جی معمولاً
   شناسهٔ پیشنهادی می‌دهد، مثل `com.yourcompany.wol`.

### شناسهٔ اپ باید همه‌جا یکی باشد

اگر شناسهٔ نهایی با `com.zcode.wol` فرق دارد، این فایل‌ها را تغییر دهید:

| فایل | مقدار |
|---|---|
| `appinfo.json` | `"id"` |
| `resources/fa/appinfo.json` | `"id"` |
| `resources/ko/appinfo.json` | `"id"` |
| `services.json` | `"name"` سرویس (قرارداد: هم‌نام با شناسهٔ اپ) |
| `js/luna.js` | `SERVICE_NAME` |
| `service/service.js` | `SERVICE_NAME` |

دو مورد آخر **باید** با `services.json` یکی باشند وگرنه اپ بالا می‌آید ولی هیچ
بسته‌ای ارسال نمی‌شود. پس از تغییر، حتماً `npm test` را اجرا کنید — آزمون همین
هم‌نامی را بررسی نمی‌کند، ولی `ares-package` و یک اجرای آزمایشی روی تلویزیون
مشکل را سریع نشان می‌دهند. اگر شک دارید، این شش جا را یکی‌یکی چشمی چک کنید.

همچنین `TARGET_VERSION` در `js/app.js` و `"version"` در `package.json` را با
`appinfo.json` هم‌گام نگه دارید.

## ۲) آماده‌سازی بسته

```bash
npm run icons      # آیکون‌ها را بسازید (اجباری)
npm test           # آزمون منطق بستهٔ جادویی
npm run package    # dist/com.zcode.wol_1.0.0_all.ipk
```

`ares-package` روی کل پوشه اجرا می‌شود، پس بدون استثنا کردن، پوشهٔ `tools/` و همهٔ
فایل‌های مستندات و پوشهٔ `.mimosa` هم داخل بسته می‌روند. اسکریپت `npm run package`
این‌ها را با `-e / --app-exclude` حذف می‌کند:

```bash
ares-package -e ".mimosa" -e "tools" -e "store" -e "dist" -e "*.md" \
             -e "package.json" -e ".gitignore" -o dist .
```

نتیجهٔ عملی: بستهٔ تمیز فقط پانزده فایل اجرایی دارد و اندازه‌اش از ۱۱۵KB به ۴۷KB
می‌رسد.

### minify

`ares-package` به‌صورت پیش‌فرض JS را minify می‌کند. این روی خروجی واقعی بررسی شده
است: نام پراپرتی‌های پروتکل luna (`returnValue`) و APIهای مرورگر (`PalmServiceBridge`،
`classList`) دست‌نخورده می‌مانند و فقط متغیرهای محلی کوتاه می‌شوند. پس بستهٔ
minifyشده همان چیزی است که در فروشگاه می‌فرستی. برای عیب‌یابی روی تلویزیون،
`npm run package:debug` نسخهٔ minifyنشده با لاگ خواناتر می‌سازد.

**تله‌ای که باید بدانی، اگر به سرویس کد اضافه می‌کنی:** در `service/service.js` هیچ
`return` سطح‌بالا نگذار. Node آن را می‌پذیرد (فایل را در تابع می‌پیچد) ولی minifier
آن را به‌عنوان اسکریپت تجزیه می‌کند و با خطای نگارشی کل بسته‌بندی را رد می‌کند:

```
Failed to minify code. Please check the source code <...\service\service.js>
```

در همان فایل به‌جای `return` از الگوی استاب بی‌اثر استفاده شده؛ همان را ادامه بده.

### امضا

برای انتشار در فروشگاه، بسته باید امضا شود. دو حالت وجود دارد و بستگی به این دارد
که Seller Lounge در آن زمان چه می‌خواهد:

- **بارگذاری بستهٔ امضانشده** و امضای آن توسط سیستم ال‌جی هنگام انتشار (رایج‌ترین حالت).
- **امضای محلی** با گواهی صادرشده از Seller Lounge، با
  `ares-package --sign packageinfo.json` که در آن `packageinfo.json` شامل شناسهٔ اپ
  و مسیر گواهی است.

صفحهٔ راهنمای Seller Lounge را در زمان ارسال ببینید؛ اگر گواهی لازم بود، از همان
پورتال درخواست کنید.

## ۳) حداقل نسخهٔ webOS

در Seller Lounge می‌توانید **حداقل نسخهٔ webOS** را تعیین کنید. برای این اپ:

- **webOS 4.0 (۲۰۱۸) و بالاتر** را انتخاب کنید. کد با این فرض نوشته شده: متغیرهای
  CSS و `Promise` و flexbox بدون پیشوند.
- اگر می‌خواهید تلویزیون‌های ۲۰۱۶ (webOS 3.0، کرومیوم ۳۸) را هم پوشش دهید، باید
  همهٔ `var(--...)` را در `css/app.css` با رنگ‌های ثابت جایگزین کنید. کار زیادی
  نیست ولی ظاهر ثابت می‌شود و تم‌پذیری از دست می‌رود. پیشنهاد نمی‌کنم؛ سهم آن
  دستگاه‌ها امروز ناچیز است.

## ۴) مجوزها

این اپ فقط به مجوز پایهٔ `internet` نیاز دارد که در `appinfo.json` اعلام شده، چون
سرویس Node برای باز کردن سوکت UDP به آن نیاز دارد.

اگر در بازبینی یا در اجرا روی بعضی نسخه‌های نرم‌افزار، سرویس نتوانست سوکت باز کند:
1. اول صفحهٔ **عیب‌یابی** اپ را روی همان تلویزیون اجرا کنید و کد خطا را ببینید.
2. با `npm run log` لاگ سرویس را بگیرید.
3. اگر خطا مربوط به دسترسی شبکه بود، از پشتیبانی Seller Lounge بپرسید کدام مجوز
   اضافه لازم است و آن را در `requiredPermissions` اضافه کنید.

از اعلام مجوزهای غیرلازم خودداری کنید؛ بازبینی ال‌جی به مجوزهای اضافی حساس است.

### requiredACG — این را حذف نکن

در `appinfo.json` فیلد `requiredACG` هست و مقدارش آرایهٔ خالی است:

```json
"requiredACG": []
```

این فیلد گروه‌های دسترسی (Access Control Group) برای فراخوانی APIهای **سیستمی**
luna را اعلام می‌کند — چیزهایی مثل `network.query`. **از webOS TV 27 به بعد این فیلد
برای همهٔ اپ‌ها اجباری است، حتی وقتی خالی باشد**، و نبودنش در بررسی صلاحیت ارسال
مشکل ایجاد می‌کند. `ares-package` هم اگر نباشد هشدار می‌دهد.

خالی بودنش اینجا **عمدی و درست** است، چون این اپ هیچ API سیستمی صدا نمی‌زند: تنها
فراخوانی luna آن به سرویس خودش (`com.zcode.wol.service`) است که جزو ACG نیست، و
اطلاعات شبکه را از `os.networkInterfaces()` داخل همان سرویس Node می‌گیرد، نه از luna
سیستمی. همین تصمیم باعث می‌شود اپ به هیچ گروه دسترسی اضافه‌ای نیاز نداشته باشد —
که هم برای بازبینی بهتر است و هم سطح حملهٔ کمتری دارد.

اگر بعداً خواستی API سیستمی اضافه کنی، باید نام گروه مربوطه را به این آرایه اضافه
کنی؛ فهرست گروه‌ها در راهنمای ACG سایت توسعه‌دهندگان ال‌جی است.

## ۵) سیاست حریم خصوصی

ال‌جی برای همهٔ اپ‌ها یک سیاست حریم خصوصی می‌خواهد. متن زیر دقیقاً با کاری که این
اپ می‌کند مطابقت دارد (فارسی برای خودتان، انگلیسی برای پورتال):

**English**

> This app collects no personal data.
>
> It makes no connection to the internet. There is no analytics, no advertising,
> no telemetry and no user account.
>
> The device names and MAC addresses you enter are stored locally on your TV and
> are deleted when you uninstall the app. Wake-on-LAN packets are UDP broadcasts
> sent only inside your local network; they are never routed to a remote server.
>
> The MAC manufacturer lookup uses a table compiled into the app; no lookup
> request is sent anywhere.

**فارسی**

> این اپ هیچ داده شخصی جمع‌آوری نمی‌کند.
>
> هیچ اتصالی به اینترنت برقرار نمی‌کند. هیچ ابزار تحلیلی، تبلیغات، تلمتری یا حساب
> کاربری وجود ندارد.
>
> نام دستگاه‌ها و آدرس‌های MAC که وارد می‌کنید فقط روی تلویزیون خودتان ذخیره
> می‌شود و با حذف اپ پاک می‌گردد. بسته‌های بیدارباش، broadcast در شبکهٔ محلی
> هستند و هرگز به سروری بیرونی فرستاده نمی‌شوند.
>
> جدول شناسایی سازندهٔ کارت شبکه، داخل خود اپ قرار دارد و هیچ درخواستی برای
> استعلام آن ارسال نمی‌شود.

## ۶) متن صفحهٔ فروشگاه (آمادهٔ کپی)

### انگلیسی

- **Title**: `Wake On LAN`
- **Category**: Utility
- **Age rating**: All ages
- **Description**:

> Wake sleeping computers, NAS drives and media players on your home network from
> your LG TV.
>
> Add a device with its MAC address — or pick it straight from the built-in
> network scan — and press Wake. The magic packet is a UDP broadcast that never
> leaves your home network: no account, no cloud, no internet connection needed.
>
> Features
> • Device list with one-tap wake and a Wake All button
> • Network scan that lists every host answering on your LAN
> • ARP cache reader, which usually finds the MAC address of devices that are
>   asleep right now — the address you cannot get anywhere else
> • Status check that tells you whether a machine actually came up
> • Built-in diagnostics, so you can see what your TV's firmware allows
> • Offline MAC manufacturer lookup
> • Backup and restore of your device list
> • English, Persian and Korean interface
>
> Please note: a TV cannot wake itself. A powered-off TV runs no code, and this
> app always runs on the TV. Use it to wake your other machines.
>
> The target device must be prepared for Wake-on-LAN first — enable the setting
> in its BIOS and network adapter, and connect it by cable rather than Wi-Fi. See
> the in-app diagnostics screen if waking does not work.

### فارسی

- **عنوان**: `بیدارباش شبکه`
- **دسته**: ابزار
- **ردهٔ سنی**: همهٔ سنین
- **توضیحات**:

> کامپیوتر، NAS و پخش‌کنندهٔ رسانهٔ خواب‌رفته در شبکهٔ خانه‌تان را از روی تلویزیون
> ال.جی روشن کنید.
>
> دستگاه را با آدرس MAC اضافه کنید — یا مستقیم از فهرست کاوش شبکه انتخابش کنید —
> و دکمهٔ بیدار کردن را بزنید. بستهٔ جادویی یک broadcast در شبکهٔ محلی است که از
> خانه بیرون نمی‌رود: بدون حساب کاربری، بدون ابر، بدون نیاز به اینترنت.
>
> امکانات
> • فهرست دستگاه‌ها با بیدار کردن تک‌ضربه‌ای و دکمهٔ «بیدار کردن همه»
> • کاوش شبکه و نمایش همهٔ میزبان‌های فعال
> • خواندن جدول ARP که معمولاً آدرس MAC دستگاه‌های خواب‌رفته را پیدا می‌کند —
>   همان آدرسی که جای دیگری پیدا نمی‌شود
> • بررسی وضعیت، برای اینکه بدانید دستگاه واقعاً روشن شد یا نه
> • عیب‌یابی درونی، برای دیدن اینکه نرم‌افزار تلویزیون چه چیزی را اجازه می‌دهد
> • شناسایی سازندهٔ کارت شبکه به‌صورت آفلاین
> • پشتیبان‌گیری و بازگردانی فهرست دستگاه‌ها
> • رابط به فارسی، انگلیسی و کره‌ای
>
> توجه: تلویزیون نمی‌تواند خودش را بیدار کند. تلویزیون خاموش هیچ کدی اجرا نمی‌کند و
> این اپ همیشه روی تلویزیون اجرا می‌شود. از آن برای روشن کردن دستگاه‌های دیگر
> استفاده کنید.
>
> دستگاه مقصد باید از قبل برای Wake-on-LAN آماده شده باشد — گزینه‌اش را در بایوس و
> کارت شبکه فعال کنید و ترجیحاً با کابل شبکه وصلش کنید. اگر بیدار نشد، صفحهٔ

## ۷) تصاویر و آیکون

| مورد | اندازه | توضیح |
|---|---|---|
| App icon (فهرست) | ۸۰×۸۰ | `icon.png` — از `npm run icons` |
| Large icon | ۱۳۰×۱۳۰ | `largeIcon.png` — از `npm run icons` |
| Store icon | ۴۰۰×۴۰۰ | `store/icon-400.png` — از `npm run icons` |
| Screenshots | ۱۹۲۰×۱۰۸۰ | حداقل ۱، پیشنهاد ۳ تا ۵ |

برای گرفتن اسکرین‌شات با کیفیت کامل:

```bash
ares-inspect --device tv --app com.zcode.wol
```

سپس در Chrome DevTools بازشده، نمای دستگاه را روی 1920×1080 بگذارید و از
پنل Screenshot عکس بگیرید. سه صحنهٔ پیشنهادی:

1. تب **دستگاه‌ها** با دو-سه دستگاه در فهرست (بیدارباش را چشم‌گیر نشان می‌دهد)
2. تب **کشف شبکه** با نتایج ARP (ویژگی متمایز اپ)
3. خروجی **عیب‌یابی** (نشان می‌دهد اپ ابزار تشخیصی دارد)

در اسکرین‌شات‌ها MAC و IP واقعی خودتان را نشان ندهید؛ از یک شبکهٔ نمونه استفاده
کنید.

## ۸) دلایل رایج رد شدن (و پیشگیری)

| دلیل | پیشگیری |

| نام تکراری | «Wake On LAN» عمومی است؛ اگر تکراری بود چیزی مثل «Wake On LAN for TV» انتخاب کنید و همه‌جا (شش جای بخش ۱) به‌روز کنید |

## ۹) بعد از ارسال

1. بازبینی معمولاً یکی-دو هفته طول می‌کشد.
2. گزارش بازبینی در Seller Lounge می‌آید؛ اگر ایراد گرفته شد، در همان نسخه اصلاح
   کنید و دوباره بفرستید.
3. برای نسخهٔ بعدی: `"version"` را در `appinfo.json`، `resources/*/appinfo.json`،
   `package.json` و `TARGET_VERSION` در `js/app.js` افزایش دهید، آیکون‌ها را دوباره
   بسازید و بستهٔ جدید را بفرستید.
4. **حالت توسعه‌دهنده روی تلویزیون خودتان** با نصب اپ از فروشگاه لازم نمی‌شود، ولی
   نشست حالت توسعه‌دهنده منقضی می‌شود؛ اگر `ares-install` کار نکرد، اپ Developer
   Mode را باز کنید و دوباره فعال کنید.
