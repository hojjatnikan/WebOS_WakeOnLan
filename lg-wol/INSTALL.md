# نصب روی تلویزیون خودت، بدون فروشگاه ال‌جی

بله، ممکن است. برای نصب روی **تلویزیون خودت** نه به حساب فروشنده لازم داری، نه به
تأیید بازبینی، نه به امضای ال‌جی. فقط یک حساب **توسعه‌دهندهٔ** رایگان و ابزار
`ares-cli`.

کد اپ در هر دو حالت یکی است؛ اگر بعداً خواستی در فروشگاه منتشرش کنی، هیچ تغییری در
کد لازم نیست.

---

## مسیر ۱ — حالت توسعه‌دهنده (رسمی، رایگان، پیشنهادی)

### پیش‌نیازها

| مورد | توضیح |
|---|---|
| تلویزیون ال‌جی با webOS 4.0+ | باید به اینترنت وصل باشد |
| حساب توسعه‌دهندهٔ ال‌جی | ثبت‌نام رایگان و فوری در `developer.lge.com`. **این با حساب فروشنده (Seller Lounge) فرق دارد** — آن یکی مدارک شرکت و تأیید چندروزه می‌خواهد، این یکی نه |
| Node.js LTS روی کامپیوتر | برای `ares-cli` |
| کامپیوتر و تلویزیون روی یک شبکه | در حالت توسعه‌دهنده، ارتباط از طریق SSH روی پورت ۹۹۲۲ برقرار می‌شود |

### گام ۱ — اپ Developer Mode را روی تلویزیون نصب کن

اپ **Developer Mode** را از فروشگاه ال‌جی روی تلویزیون نصب کن. این تنها چیزی است
که باید از فروشگاه بیاید — و اپ رسمی خود ال‌جی است، پس بلافاصله در دسترس است و
هیچ فرایند تأییدی ندارد.

### گام ۲ — آن را فعال کن

1. اپ Developer Mode را باز کن و با **حساب توسعه‌دهندهٔ** خودت وارد شو.
2. `Dev Mode Status` را روی **ON** بگذار. تلویزیون یک بار ری‌استارت می‌شود.
3. بعد از ری‌استارت، دوباره اپ را باز کن و `Key Server` را روشن کن.
4. در همان صفحه دو چیز مهم را ببین:
   - **IP Address** تلویزیون (مثلاً `192.168.1.40`)
   - یک **passphrase** شش‌کاراکتری

### گام ۳ — ابزار را روی کامپیوتر نصب کن

```bash
npm install -g @webos-tools/cli
ares -V
ares-novacom --help
```

**نام پکیج را دقیق بگیر: `@webos-tools/cli`.** پکیج‌های مشابهی وجود دارند که کار
نمی‌کنند و خطای گمراه‌کننده می‌دهند:

| پکیج | مشکل |
|---|---|
| `@webos-tools/cli` | ✅ این را نصب کن — پکیج رسمی webOS **TV** |
| `@webosose/ares-cli` | برای webOS **OSE** است، نه تلویزیون. دستورهای مخصوص تلویزیون مثل `ares-novacom` را ندارد |
| `ares-cli` | نسخهٔ قدیمی SDK؛ نصب shimهایش روی ویندوز ناقص می‌ماند |

**نسخهٔ Node:** ال‌جی بازهٔ **۱۴.۱۵.۱ تا ۱۶.۲۰.۲** را پیشنهاد می‌کند. با Node خارج
از این بازه نصب ناقص می‌ماند و بعضی دستورها ساخته نمی‌شوند.

### گام ۴ — تلویزیون را به ابزار معرفی کن

```bash
ares-setup-device
```

به‌صورت تعاملی این مقادیر را وارد کن:

| پرسش | مقدار |
|---|---|
| Device name | `tv` |
| host | IP تلویزیون از اپ Developer Mode |
| port | `9922` |
| username | `prisoner` |
| Set default | Yes |

در مستندات رسمی، `ares-setup-device` **هیچ پرسشی دربارهٔ authentication، نام فایل
کلید یا passphrase نمی‌پرسد**. فقط همان پنج مقدار بالا را می‌گیرد.

### ⚠️ اگر پرسش‌های اضافه دیدی، پکیج اشتباه است

اگر `ares-setup-device` از تو `Select authentication` پرسید و بعد نام فایل کلید و
`key's passphrase`، یعنی نسخهٔ **اشتباهی** را نصب کرده‌ای — نه اینکه مقادیر را غلط
پر کرده‌ای. این دو پرسش در نسخهٔ درست وجود ندارند.

دو خطایی که از این مسیر اشتباه بیرون می‌آید:

| خطا | علت |
|---|---|
| `All configured authentication methods failed` | `password` انتخاب شده. حساب `prisoner` روی تلویزیون **هیچ رمز عبوری ندارد** — عمداً |
| `Private key file or password does not exist` | نامی که وارد کردی به فایل کلید واقعی اشاره نمی‌کند |

و آن `passphrase` شش‌کاراکتری اپ Developer Mode در هیچ‌کدام از این دو فیلد جا
نمی‌گیرد: نه رمز SSH است، نه رمز فایل کلید محلی. یک توکن یک‌بارمصرف برای سرویس
Key Server است و فقط در گام ۵ مصرف می‌شود.

**راه‌حل، عوض کردن مقادیر نیست؛ عوض کردن پکیج است.** بخش «اگر `ares-novacom`
شناخته نمی‌شود» را ببین.

اگر خواستی ورودی فعلی را پاک کنی:

```bash
ares-setup-device -r tv
```

### اگر `ares-novacom` شناخته نمی‌شود

`'ares-novacom' is not recognized` تقریباً همیشه یعنی **پکیج اشتباه نصب شده**، نه
مشکل PATH. تشخیص قطعی: اگر بقیهٔ دستورهای `ares-*` کار می‌کنند، PATH سالم است و فقط
خودِ این دستور نصب نشده.

`ares-novacom` بخشی از `@webos-tools/cli` است. `@webosose/ares-cli` آن را ندارد.

نصب درست:

```bat
npm uninstall -g ares-cli @webosose/ares-cli @webos-tools/cli
npm install -g @webos-tools/cli
ares -V
ares-novacom --help
```

اگر بعد از این هم نبود، `node -v` را چک کن — خارج از بازهٔ ۱۴.۱۵.۱ تا ۱۶.۲۰.۲ نصب
ناقص می‌ماند. برای دیدن وضعیت فعلی:

```bat
node -v
npm ls -g --depth=0
dir "%APPDATA%\npm\ares*"
```

### گام ۵ — کلید را روی تلویزیون بنشان

این گام است که واقعاً احراز هویت را برقرار می‌کند:

```bash
ares-novacom --device tv --getkey
```

وقتی `input passphrase:` پرسید، همان شش‌کاراکتر را وارد کن. طبق مستندات ال‌جی، این
مقدار در **پایین-چپ صفحهٔ اپ Developer Mode** نشان داده می‌شود و **به بزرگ/کوچک بودن
حروف حساس است**. این گام کلید عمومی تو را روی تلویزیون می‌نشاند و از این به بعد
دیگر لازم نیست تکرار شود.

**دو نکته که اگر رعایت نشوند `getkey` رد می‌شود:**

- `Key Server` در اپ Developer Mode باید **روشن** باشد. اگر `Dev Mode Status` را
  روشن کردی و تلویزیون ری‌استارت شد، بعد از ری‌استارت باید دوباره اپ را باز کنی و
  `Key Server` را روشن کنی.
- `passphrase` هر بار که Key Server را خاموش/روشن کنی یا تلویزیون ری‌استارت شود
  **عوض می‌شود**. هر بار از روی صفحه بخوانش.

`passphrase` یک رمز عبور نیست که جایی ذخیره کنی — از روی صفحهٔ تلویزیون بخوان و در
همان پیام تعاملی وارد کن. هیچ‌جا (در فایل، در مستندات، در مخزن گیت) ثبتش نکن.

### کلیدها کجا نگه داشته می‌شوند

`ares-novacom --getkey` هنگام اجرا یک جفت کلید می‌سازد و کلید عمومی را روی تلویزیون
ثبت می‌کند. کلید خصوصی در یکی از این دو پوشه می‌ماند و از این به بعد همهٔ دستورهای
`ares-*` از همان استفاده می‌کنند:

```bat
dir "%USERPROFILE%\.ssh"
dir "%USERPROFILE%\.ares"
```

کلید دستگاه شبیه‌ساز هم آنجاست، که تأیید می‌کند پوشهٔ درست را نگاه می‌کنی. اگر بعد
از اجرای `getkey` هیچ کلید تازه‌ای اینجا ظاهر نشد، یعنی آن گام موفق نشده — پس اول
`Key Server` و `passphrase` را درست کن، نه اینکه دنبال نام کلید بگردی.

اتصال را تست کن:

```bash
ares-setup-device --list                  # فهرست دستگاه‌های تنظیم‌شده
ares-device --system-info --device tv     # تأیید واقعی اتصال
```

اگر `tv` در فهرست بود و `--system-info` اطلاعات تلویزیون را چاپ کرد، اتصال برقرار
است و می‌توانی سراغ ساخت بسته بروی.

### گام ۶ — اپ را بساز و نصب کن

```bash
cd lg-wol
npm run icons      # الزامی: بدون icon.png بسته‌بندی انجام نمی‌شود
npm test           # آزمون منطق بستهٔ جادویی
npm run package    # dist/com.zcode.wol_1.0.0_all.ipk

npm run install:tv
npm run launch
```

**minify:** `ares-package` به‌صورت پیش‌فرض کد JS را minify می‌کند و بسته را از ۱۱۵KB به
۴۷KB می‌رساند. این روی خروجی واقعی آزمایش شده: نام پراپرتی‌ها دست‌نخورده می‌ماند
(`returnValue`، `PalmServiceBridge`، `classList`) و فقط متغیرهای محلی کوتاه می‌شوند.

برای عیب‌یابی روی تلویزیون، نسخهٔ minifyنشده لاگ و stack trace خواناتر دارد:

```bash
npm run package:debug      # همان بسته، بدون minify
```

**`ares-launch --hosted` برای این اپ کار نمی‌کند.** طبق مستندات، حالت hosted نمی‌تواند
JS service داشته باشد — و کل موتور WOL این اپ یک JS service است. پس برای هر تست
باید `npm run install:tv` کامل بزنی.

### گام ۷ — همان آزمون عیب‌یابی

اپ را باز کن و برو به **تنظیمات → عیب‌یابی → اجرای آزمون**. این صفحه یک بستهٔ
واقعی می‌فرستد و می‌گوید نرم‌افزار همین تلویزیون اجازهٔ broadcast می‌دهد یا نه.
`udp.ok: true` یعنی همه چیز آماده است.

اگر خطا داد، لاگ زندهٔ سرویس را ببین:

```bash
ares-log --device tv -f
```

## ⚠️ محدودیت مهم مسیر ۱: نشست حالت توسعه‌دهنده منقضی می‌شود

این را باید بدانی چون مرتب با آن روبه‌رو می‌شوی:

- نشست حالت توسعه‌دهنده **موقت** است (پنجرهٔ فعلی اپ Developer Mode حدود ۱۰۰۰ ساعت
  یعنی حدود ۴۱ روز است؛ در نسخه‌های قدیمی‌تر بسیار کمتر بود).
- وقتی نشست منقضی شود، اپ روی تلویزیون ناپدید می‌شود یا دیگر اجرا نمی‌شود.
- تلویزیون هم باید به اینترنت وصل باشد تا نشست تازه شود.

**راه‌حل عملی:** هر ۴۰ روز اپ Developer Mode را باز کن و `Dev Mode Status` را دوباره
روشن کن. چند ثانیه کار است. برای یک اپ شخصی کاملاً قابل تحمل است.

روش جایگزین: یک `cron` روی کامپیوتر که هر ماه خودکار اپ را دوباره نصب کند. ولی
چون خود نشست روی **تلویزیون** منقضی می‌شود، آن هم بدون تازه‌سازی نشست کمکی نمی‌کند.

## مسیر ۲ — روت کردن تلویزیون (دائمی، ولی با ریسک)

اگر می‌خواهی اپ بدون انقضای ۴۰روزه دائمی بماند، باید تلویزیون را روت کنی. این کار
ممکن است ولی **ریسک واقعی دارد** و من در اینجا دستور گام‌به‌گام نمی‌دهم، چون:

- روش‌های روت به **نسخهٔ دقیق نرم‌افزار** تلویزیون وابسته‌اند. روی مدل‌های جدید
  (webOS 6.0 به بعد، و خصوصاً مدل‌های ۲۰۲۳ و بعد) بیشتر راه‌های قدیمی بسته شده‌اند.
- گارانتی را باطل می‌کند و ریسک خرابی دارد.
- بعد از هر به‌روزرسانی نرم‌افزار ممکن است از دست برود.

انجمن **webOS Homebrew** (`webosbrew.org`) مرجع این کار است: ببین `RootMyTV` و
**Homebrew Channel** روی مدل و نسخهٔ نرم‌افزار تو پشتیبانی می‌شود یا نه. آنجا یک
فهرست سازگاری به‌روز نگه می‌دارند که من نمی‌توانم از اینجا تأییدش کنم.

نکتهٔ مفید: **RootMyTV و Homebrew Channel خودشان از مسیر حالت توسعه‌دهنده نصب
می‌شوند** — یعنی برای شروع همان گام‌های بالا را انجام می‌دهی. اگر من هم می‌خواستم
روت کنم، اول مسیر ۱ را کامل می‌کردم تا مطمئن شوم اپ کار می‌کند، بعد سراغ روت می‌رفتم.

**توصیه:** با مسیر ۱ شروع کن. اگر محدودیت ۴۰روزه در عمل آزارت داد، آن‌وقت سراغ روت برو.

## عیب‌یابی نصب

| خطا | علت و راه‌حل |
|---|---|
| `'ares-novacom' is not recognized` | پکیج اشتباه نصب شده. `npm install -g @webos-tools/cli` — بخش گام ۳ |
| `All configured authentication methods failed` | نشانهٔ نسخهٔ اشتباه CLI که پرسش `Select authentication` را نشان می‌دهد. حساب `prisoner` روی تلویزیون رمز عبور ندارد |
| `[Tips]: Private key file or password does not exist` | همان نسخهٔ اشتباه CLI. راه‌حل عوض کردن پکیج است، نه عوض کردن نام کلید |
| `ares-install` می‌گوید دستگاه پیدا نشد | `ares-setup-device --list` و `ares-device --system-info --device tv` را بزن. اگر خالی بود، مراحل ۳ تا ۵ را دوباره انجام بده |
| `ares-novacom --getkey` رد می‌شود | `Key Server` در اپ Developer Mode روشن نیست، یا `passphrase` اشتباه/منقضی است، یا تلویزیون به اینترنت وصل نیست، یا IP عوض شده |
| `Error: connection refused` روی پورت ۹۹۲۲ | اپ Developer Mode بسته شده یا نشست منقضی شده؛ دوباره بازش کن |
| `getkey` خطای شبکه می‌دهد | آدرس IP را از خود اپ Developer Mode بخوان نه از تنظیمات شبکهٔ تلویزیون. `ping` بزن و مطمئن شو هر دو روی یک سابنت‌اند (روی وای‌فای، AP isolation مانع می‌شود) |
| نصب می‌شود ولی اپ بلافاصله می‌بندد | `ares-log --device tv -f` را ببین. اگر سرویس بالا نیامده باشد، خطا همان‌جا هست |
| خطای امضا هنگام نصب | بعضی نسخه‌های SDK برای نصب هم امضا می‌خواهند — بخش زیر |
| IP تلویزیون عوض شده | `ares-setup-device` را دوباره اجرا کن، یا `ares-setup-device -e tv -i host=IP_جدید` |

### اگر نصب به‌خاطر امضا رد شد

فایل `packageinfo.json` را در ریشهٔ پروژه بساز:

```json
{
  "appId": "com.zcode.wol",
  "deviceId": "tv",
  "version": "1.0.0"
}
```

و با امضا بسته‌بندی کن:

```bash
ares-package --sign packageinfo.json -o dist .
```

`ares-cli` از گواهی توسعه‌دهندهٔ پیش‌فرض خودش استفاده می‌کند. اگر لازم شد که گواهی
مخصوص خودت را بسازی، `ares-generate -c` و `ares-package --sign` را ببین
(`ares-package --help`).

**توجه:** مقدار `appId` باید با `"id"` در `appinfo.json` یکی باشد.

## ابزاری که برای تست رابط کاربری خیلی به کارت می‌آید

چون مطمئن‌ترین راه آزمایش رابط، دیدن آن روی خود تلویزیون است:

```bash
ares-inspect --device tv --app com.zcode.wol
```

یک Chrome DevTools واقعی روی اپ در حال اجرا در تلویزیون باز می‌کند: کنسول، شبکه،
و امکان تغییر زندهٔ CSS. برای تنظیم دقیق فاصله‌ها روی صفحهٔ ۱۹۲۰×۱۰۸۰ بهترین ابزار
است. از پنل Screenshot هم همان‌جا می‌توانی اسکرین‌شات ۱۹۲۰×۱۰۸۰ برای صفحهٔ فروشگاه
بگیری.
